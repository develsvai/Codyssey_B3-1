## 화면을 기록하는 방식

- 메뉴 진입, 항목 입력, 저장 직전, 저장 결과를 각각 남긴다. 펼침 메뉴나 탭 전환이 있으면 중간 화면도 추가한다.
- 파일명은 `01-console-user.png`처럼 순서와 내용을 적는다. 같은 단계의 추가 화면은 `04a`, `04b`로 구분한다.
- 원본 화면과 설명을 덧붙인 화면을 별도로 보관한다. 말풍선은 화면당 2~3개, 한 말풍선은 1~2문장으로 한다.
- 버튼에는 “무엇을 누르는지”, 입력 항목에는 “왜 이 값을 쓰는지”, 결과 화면에는 “어떤 상태면 성공인지”를 표시한다.
- 확대 화면에도 메뉴 이름이나 페이지 제목이 보이게 해서 현재 위치를 알 수 있게 한다.
- 비밀번호, 인증 코드, 세션 토큰, SSH 개인키 내용은 촬영하지 않는다.

## 촬영 순서와 말풍선 초안

| 순서 | 남길 화면 | 말풍선에 넣을 설명 |
|---|---|---|
| 01~02 | 로그인 사용자 확인 → 서울 리전 선택 | “이 사용자가 AWS 자원을 만들어요.” / “이번 자원은 서울 리전에 만들어요.” |
| 03~05 | VPC 메뉴 → 이름·주소 범위·태그 입력 → 생성 결과 | “VPC는 내 전용 네트워크예요.” / “10.77.0.0/16은 내부에서 쓸 주소 범위예요.” |
| 06~08 | 서브넷 생성 진입 → VPC·AZ·주소 범위·태그 → 생성 결과 | “방금 만든 VPC를 골라요.” / “10.77.1.0/24는 VPC 안에 들어가는 작은 범위예요.” |
| 09~12 | 게이트웨이 생성 입력 → 생성 결과 → VPC 연결 선택 → 연결 결과 | “만든 뒤 VPC에 연결해야 해요.” / “연결 대상이 이번 VPC인지 확인해요.” |
| 13~17 | 라우팅 테이블 생성 → 경로 입력 → 저장 결과 → 서브넷 연결 선택 → 연결 결과 | “기본 경로를 인터넷 게이트웨이로 보내요.” / “이 규칙을 어느 서브넷에서 쓸지 연결해요.” |
| 18~20 | 보안 그룹 생성 → HTTP·SSH 규칙 입력 → 저장 결과 | “웹 접속은 80번이에요.” / “관리 접속 22번은 내 IP 하나만 허용해요.” |
| 21~22 | 키페어 가져오기 → 등록 결과 | “서버에는 공개키를 등록해요.” / “개인키는 내 컴퓨터에 보관해요.” |
| 23~26 | EC2 생성 진입 → AMI·유형 선택 → 태그 적용 대상 → 키페어 선택 | “AMI는 운영체제 등이 담긴 시작 틀이에요.” / “유형은 컴퓨터 사양이에요.” |
| 27~30 | VPC·서브넷·공인 IP → 기존 보안 그룹 선택 → 디스크 설정 → 생성 전 요약 | “직접 만든 네트워크와 보안 그룹을 골라요.” / “디스크는 gp3 8 GiB로 설정해요.” |
| 31~32 | 실행 상태 → 세부 정보의 공인 IP·내부 IP | “컴퓨터가 실행 중이에요.” / “브라우저 접속에는 새 공인 IP를 사용해요.” |
| 33~36 | SSH 접속 → Nginx 설치 → 파일·설정 적용 → 설정 검사·내부 응답 | “이제 명령이 실행되는 곳은 AWS 컴퓨터예요.” / “localhost는 이 서버 자신이에요.” |
| 37~38 | 외부 브라우저 홈페이지 → /health와 응답 확인 | “내 컴퓨터에서 보낸 요청에 서버가 응답했어요.” / “200과 ok가 보이면 이번 상태 확인 요청은 성공이에요.” |
| 39~42 | HTTP 규칙 제거 → 새 연결 실패 → 규칙 복구 → 새 연결 성공 | “서버는 켜져 있어도 통신 규칙에 따라 접속이 달라져요.” |
| 43~44 | EC2 종료 확인 → 종료 상태·디스크 제거 확인 | “콘솔 창을 닫는 것과 서버를 종료하는 것은 달라요.” |
| 45~47 | 보안 그룹·서브넷·별도 라우팅 테이블 정리 → 게이트웨이 분리·삭제 → VPC·키페어 삭제 | “연결된 자원부터 풀고, 내 실습 자원만 정리해요.” |
| 48 | 남은 실습 자원 확인 | “서버뿐 아니라 디스크와 연결 자원도 남지 않았는지 확인해요.” |

번호 범위 안의 클릭과 화면 전환도 각각 캡처한다. 특히 EC2 생성 화면은 길어서 입력 항목별로 나누고, 정리 단계도 자원별로 나눈다. 최종 장수는 실제 콘솔 흐름에 따라 늘어날 수 있다.

## 재구축 전에 준비할 것

현재 과제 정책은 CLI로 검증했다. 브라우저 조작·캡처 연결과 콘솔에서 필요한 조회·생성 권한을 먼저 확인한다. 콘솔의 실제 화면에 맞춰 촬영 목록을 조정한다.

- 기존 정책은 키페어의 `ImportKeyPair`를 허용한다. 로컬에서 준비한 공개키를 가져오는 경로로 진행한다.
- 생성 시 `Project=Codyssey-B3-1`, `Owner=Haru2_freetier_iam_user` 태그가 필요하다. EC2 생성 때는 인스턴스·볼륨·네트워크 인터페이스에 적용되는지도 확인한다.
- 이름은 다른 사람의 자원과 구분되도록 붙인다. 생성된 자원 ID는 이번 실행의 값으로 따로 기록한다.
- SSH 규칙에는 촬영 장소의 현재 공인 IP를 쓴다. 19일 장소가 달라지면 관리 접속 허용 IP도 다시 확인한다.
- 첫 실습의 홈페이지와 Nginx 설정을 재사용한다. 홈페이지 문구에 실제와 다른 IP나 완료 상태가 표시되지 않는지 확인한다.
- 사용자 선택: 새 서버는 19일까지 실행 상태로 유지한다. 자동 종료는 설정하지 않았다.

## 45분 진행 팁

생성 대기는 저장한 캡처로 이어가고, 실제 화면에서는 공인 IP로 페이지 열기와 짧은 접속 실패·복구를 중심으로 보여준다. 장애 시연은 내 실습 인스턴스의 HTTP 규칙에만 적용하고 SSH 규칙은 유지한다. 복구 후 새 연결의 성공까지 확인한다.

마지막 정리는 첫 과제의 정리 기록과 체크리스트로 설명한다. 이번 재구축에서는 삭제 화면을 촬영하지 않았다. 질문이 많으면 장애 시연을 줄이고, “브라우저에서 서버까지 어떤 요소가 필요했는지” 함께 구성도를 읽는다.
